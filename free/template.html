1. Why this exists

Most agents fail because they start as a clever prompt. Production agents start as a job design: clear outcome, constrained tools, memory rules, stop conditions, and a place in a real workflow.

2. Agent Design Sheet (fill this)

Job / Outcome (one sentence, verifiable)
Owner (who improves it from real usage)
Inputs (required data + format)
Tools allowed (list only what is necessary)
Memory rules (what is stored, how long, what is excluded)
Output contract (exact format downstream needs)
Stop conditions (success / max steps / max cost / escalate)
Failure handling (retry / fallback / human gate)
Success metrics (how you know it works in production)

3. Six-step build path

  • Step 1 — Define one verifiable outcome
  • Step 2 — Map the current human process
  • Step 3 — Choose architecture (default: single constrained agent)
  • Step 4 — Design role, tools, memory, output
  • Step 5 — Connect only required tools
  • Step 6 — Install, measure, iterate

4. Four layers (diagnose failures here)

Prompt — instructions for a single call
Context — everything the model sees
Harness — tools, retries, permissions, limits
Loop — when to continue, stop, or escalate

Prompt packs only touch the first layer. Most production failures live in the other three.

5. Failure modes to design against

  • Context drift across long runs
  • Silent tool failures treated as success
  • Unbounded loops / cost blowups
  • Ghost actions (claims success without executing)
  • Cascading errors with no rollback
  • No observability
